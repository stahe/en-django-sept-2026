## Overview

This course provides a step-by-step guide to building an MVC web application using the **Django 6.1** framework and the **Python 3.13** language. HTML pages are generated by the server using **Django templates** (the DTL language), without a browser-side JavaScript framework. Data access is handled via the **Django ORM**.

It adapts the course [Step-by-Step Introduction to the [Symfony](https://stahe.github.io/en-symfony-sept-2026/) Web Framework]—which itself is based on the [Laravel](https://stahe.github.io/en-laravel-sept-2026/) courses— [Flask](https://stahe.github.io/rn-flask-sept-2026/), [Spring MVC](https://stahe.github.io/en-springmvc-sept-2026/), [ASP.NET Core MVC](https://stahe.github.io/en-aspnetcoremvc-sept-2026/), and [NestJS](https://stahe.github.io/en-nestjs-html-sept-2026/). The examples have the same numbers and cover the same topics, so you can compare the frameworks example by example.

## Contents

| Chapter | Topics | Examples |
|---|---|---|
| Views, Routing, Responses | routes (`urls.py`, `path`, `include`), views, responses, redirects, middleware, shared services | 01–06 |
| The View Model | request parameters, data classes, forms as validators, decorators, POST requests, and JSON | 07–12 |
| Templates and Forms | DTL, parent templates, named fragments, context processors, tags and filters, Django forms, Post/Redirect/Get, messages, CSRF protection | 13–21 |
| Internationalization | An application in French and English (gettext: `.po` and `.mo` files, plurals) | 22 |
| Data Scopes | request, session, cache, signed cookies | 23 |
| The Request Lifecycle | middleware, signals, error pages | 24 |
| Authentication and Authorization | JWT token in a cookie, roles, CAPTCHA, rate limiting | 25–27 |
| Layered Architecture | Web / Business Logic / DAO using Django’s ORM and MySQL, transactions, optimistic locking | 28 |
| Case Study | **RdvMedecins**, a medical appointment scheduling application, explained file by file | - |

The `rdvmedecins2-django` case study manages three roles (administrator, doctors, patients): calendars, reservations, doctor and client management, CAPTCHA-protected account creation, and a French/English interface. It uses the same `dbrdvmedecins2` database as the other versions of the application.

## Prerequisites

- Python 3.12 or newer (tested with 3.13), with `pip` and `venv`;
- MySQL 8.4 or newer, or MariaDB 10.11 or newer (Laragon on Windows);
- Visual Studio Code with the Python, Pylance, and Django extensions;
- curl.

The code is available for download from the course website. The virtual environments (`.venv` folders) are not included there: run `python -m venv .venv` followed by `pip install -r requirements.txt` to create them—one in the `examples` folder and one in the `rdvmedecins2-django` folder.
